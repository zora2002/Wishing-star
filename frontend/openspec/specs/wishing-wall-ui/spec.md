## Purpose

許願牆前端頁面，讓使用者瀏覽現有的願望、輸入姓名與願望內容送出，並即時看到自己剛送出的願望出現在牆上。

## Requirements

### Requirement: 顯示願望列表
系統 SHALL 在頁面載入時向後端取得所有願望，並以星星飄過夜空的方式呈現，而不是條列文字。願望依建立時間新到舊排入播放順序。

#### Scenario: 頁面載入時顯示現有願望
- **WHEN** 使用者開啟許願牆頁面
- **THEN** 系統呼叫後端 API 取得願望列表，並依建立時間新到舊，把每則願望排入星星播放佇列

#### Scenario: 目前沒有任何願望
- **WHEN** 後端回傳的願望列表是空的
- **THEN** 系統顯示夜空與天際線背景，不顯示任何星星，也不顯示提示文字

#### Scenario: 讀取願望列表失敗
- **WHEN** 頁面載入時取得願望列表的 API 呼叫失敗（例如伺服器錯誤或網路中斷）
- **THEN** 系統顯示錯誤提示，讓使用者知道願望牆暫時載入不出來

### Requirement: 提交新願望
系統 SHALL 提供姓名與願望內容的輸入欄位，並在使用者送出時建立一則新願望。

#### Scenario: 成功送出願望
- **WHEN** 使用者填寫願望內容（可不填姓名）並按下送出
- **THEN** 系統呼叫後端 API 新增願望，成功後將新願望加入畫面上的列表，並清空輸入欄位

#### Scenario: 願望內容為空
- **WHEN** 使用者在願望內容為空的情況下按下送出
- **THEN** 系統在畫面上顯示「願望內容不能是空的」之類的提示，且不呼叫後端 API

#### Scenario: 願望內容輸入時已達上限
- **WHEN** 使用者在願望內容欄位輸入文字，且內容已達 20 字
- **THEN** 系統阻止再輸入更多字元，欄位內容不會超過 20 字

#### Scenario: 願望內容超過長度限制
- **WHEN** 使用者輸入超過 20 字的願望內容並送出
- **THEN** 系統在畫面上顯示長度超過限制的提示，且不呼叫後端 API

#### Scenario: 未填寫姓名
- **WHEN** 使用者沒有填寫姓名就送出願望
- **THEN** 系統仍正常送出，並顯示後端回傳的預設姓名（例如「匿名的小生物」）

#### Scenario: 姓名超過長度限制
- **WHEN** 使用者輸入超過 6 字的姓名並送出
- **THEN** 系統在畫面上顯示長度超過限制的提示，且不呼叫後端 API

#### Scenario: 送出願望失敗
- **WHEN** 新增願望的 API 呼叫失敗（例如伺服器錯誤）
- **THEN** 系統顯示錯誤提示，保留使用者已輸入的內容，不清空輸入欄位

### Requirement: 可設定後端 API 網址
系統 SHALL 透過環境變數設定要呼叫的後端 API 網址，不把網址寫死在程式碼裡。

#### Scenario: 使用環境變數指定的 API 網址
- **WHEN** 建置或啟動時有設定 `VITE_API_URL`
- **THEN** 系統呼叫該網址下的 `/api/wishes` 端點

#### Scenario: 未設定環境變數時使用本機預設值
- **WHEN** 沒有設定 `VITE_API_URL`
- **THEN** 系統預設呼叫 `http://localhost:4000/api/wishes`

### Requirement: 整體版面呈現
許願牆 SHALL 以置中卡片式構圖呈現：星空場景是一張尺寸有上限的卡片，願望輸入表單是星空卡片下方另一張獨立卡片，頁面背景鋪滿整個瀏覽器視窗，不顯示額外的頁面標題文字。

#### Scenario: 開啟許願牆頁面
- **WHEN** 使用者開啟許願牆頁面
- **THEN** 頁面背景鋪滿整個瀏覽器視窗並置中顯示內容；夜空、星星、天際線呈現在一張寬高有上限的星空卡片內，願望輸入表單是星空卡片下方另一張獨立卡片，畫面中沒有標題文字

### Requirement: 月亮裝飾
天空面板 SHALL 顯示一個靜態弦月裝飾，固定在畫面左上角，不論願望數量多寡都要顯示。

#### Scenario: 願望牆顯示中
- **WHEN** 願望牆顯示中，不論目前有沒有願望
- **THEN** 畫面左上角持續顯示一個弦月圖形

### Requirement: 星星外觀與位置
每顆星星 SHALL 從 macaron 色票中隨機取一個顏色、隨機取一個旋轉角度，並以不規則的上下交錯位置顯示，星星之間的出現間距也 SHALL 是隨機的，不排成單一列或固定網格。

#### Scenario: 畫面上同時有多顆星星
- **WHEN** 天空面板上同時顯示兩顆以上的星星
- **THEN** 它們位在不同的垂直位置、呈現不同的旋轉角度，且不是同時間開始飄動

### Requirement: 願望詳情懸浮顯示
使用者將滑鼠移到星星上時，系統 SHALL 在星星右側顯示願望詳情文字，格式為「願望 — 名字」（以 em dash 分隔），文字本身不帶背景框或外框。

#### Scenario: 使用者將滑鼠移到星星上
- **WHEN** 使用者的滑鼠指標停在某顆星星上
- **THEN** 星星右側顯示該願望的內容，接著一個 em dash（—），再接著許願人姓名，純文字呈現、沒有背景卡片

#### Scenario: 使用者移開滑鼠
- **WHEN** 滑鼠指標離開星星
- **THEN** 願望詳情文字消失

### Requirement: 星星輪播佇列與同時上限
天空面板 SHALL 同時最多顯示 7 顆星星。願望 SHALL 依新到舊播放；當目前輪播中最舊一則願望的星星飄出畫面左側後，佇列 SHALL 回頭從最新一則願望重新開始播放。若願望總數少於 7 則，多出的位置 SHALL 保持空白，不得重複顯示同一則願望來湊數。

#### Scenario: 願望總數超過 7 則
- **WHEN** 願望牆上的願望總數超過 7 則
- **THEN** 天空面板上任何時刻顯示的星星都不超過 7 顆

#### Scenario: 輪播到最舊一則願望
- **WHEN** 目前輪播週期中最舊一則願望的星星飄出天空面板
- **THEN** 下一顆出現的星星是最新一則願望，重新開始一輪播放

#### Scenario: 願望總數少於 7 則
- **WHEN** 願望牆上目前只有例如 3 則願望
- **THEN** 同時最多只顯示 3 顆星星，且不會重複播放同一則願望來填滿其餘位置

### Requirement: 新願望優先播放
使用者新送出的願望 SHALL 被視為佇列中最新的一則，並 SHALL 在送出後不久就被排入即將播放的星星位置，而不需要等現有願望的整輪播放完畢才輪到它。

#### Scenario: 送出願望時其他願望正在播放
- **WHEN** 使用者送出新願望時，天空面板上已經有其他願望的星星正在飄動
- **THEN** 新願望的星星被排進接下來幾個即將播放的位置，而不是排到目前這輪播放的最後面

### Requirement: 天際線背景與燈窗
天空面板 SHALL 顯示靜態的城市天際線剪影，並附帶數個暖色調的小型亮燈光點作為點綴，不論目前有沒有願望都要顯示。

#### Scenario: 天際線一律可見
- **WHEN** 願望牆顯示中，不論目前有沒有願望
- **THEN** 天際線剪影與其亮燈光點都顯示在天空面板底部

### Requirement: 背景裝飾星點
天空面板 SHALL 另外顯示一批不對應任何願望的裝飾性靜態星點，以明暗交替閃爍呈現夜空氛圍，不論願望數量多寡都要顯示。

#### Scenario: 天空面板顯示中
- **WHEN** 願望牆顯示中，不論目前有沒有願望
- **THEN** 畫面中持續看得到數個明暗閃爍的裝飾星點，且它們不代表任何特定願望

### Requirement: 送出願望的動畫回饋
願望成功送出後，系統 SHALL 在畫面中央短暫播放一個星星綻放動畫作為回饋，動畫播放完畢後才清空輸入框內容。

#### Scenario: 成功送出願望
- **WHEN** 使用者送出的願望通過驗證，且後端成功建立
- **THEN** 畫面中央出現星星綻放（放大並發光後淡出）的短暫動畫，動畫播放期間輸入框內容維持原樣，動畫結束後才清空

#### Scenario: 送出失敗
- **WHEN** 送出願望的 API 呼叫失敗
- **THEN** 不播放星星綻放動畫，輸入框內容維持不清空，並顯示錯誤提示

### Requirement: 願望列表即時更新（輪詢）
系統 SHALL 定期重新取得願望列表，讓其他使用者送出的願望能以星星形式出現，不需要手動重新整理頁面。每次輪詢 SHALL 等待前一次的回應完成後才排下一次，避免請求重疊。輪詢間隔 SHALL 以十秒為單位計算，不得採用秒級（10 秒以內）的間隔。當瀏覽器分頁不可見時，輪詢 SHALL 暫停，分頁恢復可見時再繼續。

#### Scenario: 其他訪客送出願望
- **WHEN** 另一位訪客送出願望時，此使用者的分頁是開啟且可見的
- **THEN** 該願望的星星最終會出現在此使用者的天空面板上，不需要重新整理頁面

#### Scenario: 分頁在背景執行
- **WHEN** 瀏覽器分頁不可見（例如使用者切到其他分頁）
- **THEN** 系統停止輪詢，直到分頁恢復可見才繼續

#### Scenario: 輪詢請求尚未完成
- **WHEN** 一次輪詢請求還沒有完成
- **THEN** 系統不會在這次請求完成前發出下一次輪詢請求

### Requirement: 願望輸入框視覺呈現
願望送出表單 SHALL 呈現為星空卡片下方一張獨立的卡片，寬度隨視窗縮放但不超過一個上限。願望內容欄位 SHALL 顯示在上方、寬度撐滿表單卡片；姓名欄位 SHALL 顯示在下一列、寬度較窄，並與送出按鈕同列。兩個欄位 SHALL 顯示為底線樣式的輸入框（不帶外框或底色），不以冒號或其他符號分隔，並 SHALL 使用紙飛機造型的圖示作為送出按鈕，取代文字按鈕。

#### Scenario: 檢視願望送出表單
- **WHEN** 使用者檢視願望送出表單
- **THEN** 表單呈現為星空卡片下方一張獨立卡片；願望內容欄位在上方、撐滿卡片寬度，姓名欄位與送出按鈕在下一列，兩個欄位都是底線樣式的獨立欄位、彼此之間沒有分隔符號，送出按鈕是紙飛機圖示，沒有「enter」文字標籤

### Requirement: 頁尾 GitHub 連結
許願牆頁面 SHALL 在願望輸入表單卡片下方、頁面置中處，顯示一個文字連結「GitHub@zora2002」，連到專案的 GitHub 頁面，且不使用任何圖示。

#### Scenario: 檢視許願牆頁面
- **WHEN** 使用者開啟許願牆頁面
- **THEN** 願望輸入表單卡片下方顯示純文字連結「GitHub@zora2002」，不帶任何圖示

#### Scenario: 點擊 GitHub 連結
- **WHEN** 使用者點擊「GitHub@zora2002」連結
- **THEN** 系統在新分頁開啟 `https://github.com/zora2002/Wishing-star`，目前頁面保持不變
